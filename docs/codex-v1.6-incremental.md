# Codex 指令：Overcooked2-Haptics v1.6（已确认 Combo A + 长负反馈）

请先完整阅读本仓库已有代码及 docs，另外阅读同目录的 `触觉重设计_v1.6_完整实施方案.md` 和 `haptic_patterns_v1.6.json`。**本任务是在原有 Overcooked2-Haptics 项目上做增量优化，不允许重建仓库、覆盖稳定逻辑或擅自删除星级庆祝音乐和既有功能。**

## 已经由用户确认的产品行为

1. **Combo 使用方案 A**：仅当真实 Combo 档位上升时，触发对应的 ×2/×3/×4 特殊触觉；其他成功上菜（包括档位保持、等级上限后继续正确上菜）只触发一次 90ms 左右的清脆高频成功震动。Combo 与成功永不重复叠加。
2. 真正上菜失败、订单超时、食物烧焦、起火等**稀有负面事件应有更长、更沉重的低频体感**。当前初稿：拒单430ms、超时505ms、烧焦470ms（Hook 未验证先禁用）、起火820ms。不得把“乱序但上菜成功”误判为真正拒单。
3. **乱序成功 = 轻低频双段，约315ms**；真正拒单 = 长低频衰减段；起火 = 最长最重且可抢占。不要只通过调大震动强度区分。
4. 减少触觉噪音：默认关闭拾取、连续切菜、投掷、接住的震动；危险只在状态变化时优先提醒，持续火灾最多每5秒提醒一次且可关闭；一个交付/订单只发一个主反馈。
5. 保留原有1～4星庆祝音效和震动，星级达标时替代同一交付普通成功和 Combo 震动，火灾可抢占。音量 65% 的原用户选择不要擅自改变。
6. 大众手柄优先走 **XInput**（Xbox/飞智 XInput/可用的虚拟 Xbox），多玩家手柄映射必须可靠；SDL3 和原生 Steam Input 是**单独评估的可选后端**，不同后端不得重复震动同一物理设备。

## 分阶段实施

A. 审计现有实现，列出重复触发点、已有 Hook 的证据、Combo 等级信息来源、手柄输出后端与已测设备，不要先入为主改动。若无法访问游戏安装目录/实体手柄，明确哪些需要用户提供或实机确认。

B. 将 v1.6 配置作为候选预设接入现有波形配置系统，保留旧设置可回滚；确保参数校验、失败安全退出、归零、事件抢占、去重和日志。

C. 先实现 `delivery_success / delivery_out_of_order / delivery_rejected` 三者的语义隔离，再实现 Combo A 状态机。`_wasCombo=false` 不是乱序的充分证据；无法确认时播放普通成功，不猜测。

D. 实现较长的负面反馈：真实拒单、订单超时、烧焦预警、起火上升沿与火灾状态提醒。**food_burned** 只有找到独立可靠的客户端游戏事件之后才启用。

E. 做单元测试、FakeBackend 模拟、每个手柄独立预算/抢占测试，以及断连/暂停/失焦安全测试。完成 Windows 实机手柄 A/B 测试和关卡真实测试后才能声称已验收。

F. 持续更新 `docs/hook-research.md`、`docs/test-report.md`、`CHANGELOG.md`；最终提供本次修改文件、测试证据、已测设备和仍需人工判断的问题。

## 必须保留的用户协作偏好

用户特别愿意参与设计。遇到影响玩法体验的歧义、新功能、重要架构取舍、明显更好的建议，应主动给出方案和利弊，并询问用户；不得私自加入未获确认的玩法或声效。已经确定的需求和常规 Bug 修复可直接推进，无须因小问题频繁中断。**此次延长失败类反馈的总体方向已获确认，具体波形数字仍是待实测候选，不应声称已定稿。**

## 交付验收门槛

- 成功仅一声短促；拒单明显沉闷拖尾；乱序成功轻低频两段；Combo x2/3/4 只有升级才触发。
- 若火灾中断 Combo/星级，不允许后续重播过时奖励。
- XInput 多设备不会同一物理设备重复输出；不同手柄间不串震。
- 所有测试按 `docs/test-report.md` 记录“自动测试通过 / 实机已测 / 未测试”；严禁凭编译成功宣称手感和游戏事件已验证。
