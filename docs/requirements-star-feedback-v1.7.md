# Overcooked2-Haptics · 星级反馈重设计 v1.7

**性质**：基于现有 Overcooked2-Haptics 的增量开发需求；不是新 MOD，也不代表已在真实游戏中实现。  
**优先级**：本文件的 v1.7 星级规则覆盖 v1.6 中“1～4 星均播放庆祝音效”的旧要求，v1.6 的 Combo A、稀有失败长低频、设备映射、安全归零等保持有效。

## 0. 用户确认的最终产品行为（不可自行更改）

1. **1 星**：不播放任何 MOD 星级音乐/提示音，仅一段很轻的星级触觉；可选短视觉进度提醒，默认关闭。
2. **2 星**：不播放任何 MOD 星级音乐/提示音，仅轻量但与 1 星不同的触觉；视觉同上。
3. **3 星**：增加**一段短促、快乐、明确表示三星进度**的独立音效；建议 **0.8～1.3 秒**，默认目标 1.0 秒。配合轻量触觉；不是长庆典、没有欢呼掌声。它与 Combo ×3 不能混淆。
4. **4 星**：在本局首次确认当前分数越过真实四星门槛时，**立即播放约 10 秒专属庆祝音乐**，默认音乐音量 65%。建议可混少量真实欢呼与掌声。专属震动只在前约 0.5～0.8 秒输出，**不允许跟随音乐持续震动 10 秒**。
5. **危险提醒优先**：起火/烧焦警告可马上抢占星级触觉；4 星播放期间如出现紧急危险，应优先保证游戏提示可听，MOD 音乐至少立即衰减（ducking）；推荐起火持续时淡出并停止，不在危险解除后补播被取消的庆典。
6. **Combo 方案 A 保留**：只在游戏可验证的 Combo 等级上升时播放专属震动；其他正确上菜只触发一次约 90ms 清脆短震。
7. **稀有失败长低频保留**：真正上菜失败约 430ms、乱序成功约 315ms、订单过期约 505ms、食物烧焦约 470ms（独立 Hook 验证前关闭）、起火约 820ms。这些是待硬件校准的候选，不是官方标准。
8. 各事件不可叠震；不因音效接入而修改游戏分数、难度、网络同步、原游戏音乐或订单处理规则。

## 1. 触觉 + 音频设计

| 事件 | 触觉草案 | 音频 | 目的 |
|---|---|---|---|
| 1 星首次达标 | 右高频马达 H0.32 55ms | **无** | 被动进度感知 |
| 2 星首次达标 | H0.33 45ms → 停顿 55ms → H0.40 45ms | **无** | 双拍轻提示，区别于 1 星 |
| 3 星首次达标 | H0.40 60ms → 停顿 70ms → H0.53 120ms | **1.0s 短音效** | 短、完整的三星“进度到了”反馈 |
| 4 星首次达标 | H0.47 70ms → 静默70ms → H0.56 70ms → 静默70ms → H0.66 110ms → 静默70ms → H0.76/L0.14 170ms（总630ms） | **约10s**，含少量欢呼掌声 | 唯一完整胜利庆典 |

L/H 是 XInput 左低频/右高频速度的归一化命令值，不代表准确物理频率；播放器仍乘设备主增益（候选 0.75）。对单马达等手柄，节奏比“左右高低频”差异更重要。上述波形全部可配置、需要 A/B 盲测。

### 三星短音效的制作规范

- 设计为**独立、明亮、欢乐、轻盈且有完成感的音乐短句**，开头立即可感知，结尾自然利落。可用木琴/钢琴＋短铜管上行，不使用完整胜利交响乐、长混响、人群欢呼或掌声。
- 建议 WAV 48kHz、16bit 或可被现有游戏音频管理器可靠解码的 OGG；PCM 立体声/单声道均可，避免削波。建议 0.8～1.3 秒，非硬编码检查必须严格等于 1 秒。
- 三星音量默认为 65% 的 MOD 音效总增益，不代表真实响度百分比；应有独立 `star3_volume` 选项。
- **音色与 Combo ×3 区分**：三星采用“短-长”两拍加独立声音；Combo ×3 为三拍高频且无三星短曲。
- 声音资产目前只是占位路径 `audio/star3_progress_short.wav`，不代表文件已经存在。应允许用户选择现有授权文件，测试时使用有许可来源的测试音，缺失时只触觉、记录警告，不崩溃。

### 四星长音乐制作与播放

- 目标是 9～11 秒（推荐 10 秒）的快节奏欢乐胜利音乐；4 星可以在后段加入短促的人群欢呼和掌声，但音效的许可、来源单独维护。
- 0～0.7s：瞬间辨识的胜利主题 + 对齐震动重音；0.7～4s：快节奏欢乐推进；4～7s：气氛升级；7～9s：欢呼/掌声点缀；9～10s：干净收尾。
- 默认播放 1 次，不循环、不以延长原先 3 秒片段的简单循环冒充完整 10 秒庆典，不在关卡中途打断原游戏音频流。
- `AudioSource` / 现有音频系统应预加载；音频创建、播放、停止、淡入淡出在 Unity 主线程安全执行；Hook 只发布事件。
- 默认音量 `0.65`；独立开关、单独试听、音频素材路径可配置；缺失时星级判定和专属震动仍可运行。
- `audio/star4_victory_10s.wav` 仅为占位路径；**交付前如未提供真实 10s 成品，明确标为待用户提供素材**。

## 2. 实时分数、阈值和去重策略

- 从已验证的游戏状态获取当前关卡、模式、人数、队伍、权威实时分数、实际 1～4 星门槛；不得硬编码全关卡统一分数线。
- 四星并非所有关卡都可获得：无合法 4 星门槛时禁用四星达成逻辑，保留 1～3 星反馈。
- 同一局同一队伍每星最多触发一次。得分回落再跨线不得重播；重开关卡/新局必须产生新的会话 ID/epoch，重新计数。
- 一次分数更新跨过多个门槛：仅播放**本次跨过的最高星级**，其余标为已达成，防止叠音/叠震。
- MOD 中途加载时先建立分数基线，默认不追播已经取得的星级；若不能可靠取得门槛、分数、局 ID，关闭星级反馈并记录具体原因。
- 星级从“当前分数达线”触发，不将其表述为“最终结算必然获得四星”。

## 3. 与普通上菜、Combo 和危险的仲裁

**优先级**：`起火/紧急危险 > 本次星级里程碑 > 真实拒单/订单过期（独立事故） > Combo 升级 > 乱序成功 > 正常上菜`。

- 同次上菜事件与分数更新用现有安全 correlation ID `(session,team,delivery/scoreCommit)` 合并。建议先沿用当前约 80ms 合并窗，实测网络/客户端延迟后再调整，不能阻塞 Hook。
- **一次上菜最多一个主要震动**：若由这次上菜达到三星，三星触觉＋三星短音效替换成功和 Combo；达到四星则四星触觉＋10 秒音乐替换；一、二星只触觉同样替换。
- 一、二星没有音效，不要错误调用播放空 clip 或回落播放旧的 1/2 星 jingle。
- 4 星音乐期间，普通成功/Combo 触觉可恢复（如不与当前庆典震动相冲突），但不要重复播放任何星级音乐；第一次四星触觉结束后不要霸占手柄 10 秒。
- 火灾上升沿立即 `StopRumble` 并执行火灾震动，同时在 **100～200ms** 内降低四星音乐音量至不妨碍游戏警告的程度（推荐 < -18dB 相对当前 MOD 音量），持续事故可进一步淡出停止；不在火势解除后重新播放旧庆祝。
- 订单到期、失败等重要声音也可以使 MOD 音效短暂降低音量，但不要为了每个轻微成功让四星音乐忽大忽小。
- 退出/暂停/重开/切场景/卸载/掉设备时要停止或淡出 MOD 音效、并确保震动马达归零；尊重现有失焦暂停策略。

## 4. 手柄与音频输出兼容性

- 保留 v1.6 的 `IControllerRumbleBackend`，首选 XInput，未来 SDL3/Steam Input 为可选后端，**一个物理设备仅允许一个活动震动输出通道**。
- 个人成功/失败默认只路由可确认的本地操作手柄；星级是团队进度，默认对本地同队伍有效手柄轻震，但 **本机音效只能播一次**，不能按手柄人数重复播放声音。
- 对只有一个马达的设备，不应照搬左右马达不同强弱；使用节奏和时长区分事件。
- 保留每手柄增益、最短可感觉脉冲、低/高马达能力检查、单设备 Stop/断连处理，测试 Xbox 类、黑武士 5 Pro XInput、以及 Steam Input 虚拟 XInput（若硬件可得）。

## 5. 配置和兼容性迁移

- 提供 `star1/2/3/4` 独立启停、`star3_audio_enabled=true`、`star4_audio_enabled=true`、`star1/2_audio_enabled=false`（并强制不触发音频），`music_volume=0.65`、`enable_visual_progress=false`。
- 原 v1.6 旧配置中存在通用 `star_milestone`，**必须迁移为单一星级调度入口**，杜绝旧版通用星级反馈和新版分星级反馈同时执行。
- 允许用户在 3 星、4 星分开指定音效文件；旧 1～3 星音乐必须停止自动播放，但不要删除旧文件或者修改用户已有资源。
- 配置迁移后持久化方式按原有项目实现，带备份/迁移日志；如果旧配置未存在，不生成破坏性覆盖。
- 不依赖新增常驻 Python/Node/外部云服务；不要因为音乐功能改变原有游戏玩法。

## 6. 推荐实施阶段

1. **审计当前仓库**：列出 Hook、星级 tracker、音效播放器、通用 `star_milestone`、Combo/危险仲裁，以及真实文件路径，和用户确认变更边界。
2. **建立新配置和迁移**：引入四档星级策略，确保 1～2 不走音频，3 星短音，4 星长音；保留其余 v1.6 波形。
3. **重做 StarMilestoneTracker**：可靠阈值、单局首次、一次多星只最高、New Game+ 四星门槛、联机队伍状态。
4. **事件协调器整合**：保证与成功、Combo A、乱序、失败单一事件替代；紧急危险可以抢占。
5. **音频控制器**：预加载、音量 65%、星级单独音频、危险 ducking/stop、退出清理、缺文件降级。
6. **设备兼容**：多玩家队伍轻震范围、本机单次播放、XInput 映射校准及缺马达节奏降级。
7. **测试并交付**：先离线模拟（含 FakeBackend/FakeAudio），再实际控制器、游戏联机测试；更新 `docs/hook-research.md`、`docs/test-report.md`、`CHANGELOG.md`。

## 7. 最低验收矩阵

| 情况 | 期望 |
|---|---|
| 达 1 星 | 只有一次轻震，不播音乐音效；视觉默认关闭 |
| 达 2 星 | 双拍轻震，无音乐；不会与成功上菜叠震 |
| 达 3 星 | 一次约 1 秒独立短音效＋短/长两拍轻震，无欢呼；不会与 Combo ×3 混淆 |
| 达 4 星 | 首次达线立即播放 9～11 秒音乐＋前 0.5～0.8 秒专属震动，正常持续游戏 |
| 4 星播放中起火 | 火灾震动马上抢占；MOD 音乐快速降低/停止，不掩盖游戏警告 |
| 达 3/4 星同时 Combo 升级 | 星级替代 Combo/成功反馈，绝不三重叠震 |
| 达 3/4 星音频文件缺失 | 提示缺失、保留触觉；游戏无崩溃 |
| 一次跳过两个星级 | 只触发最高档，不补播较低星级音效 |
| 当前模式无四星 | 不触发四星、不误认分数门槛 |
| 分数下降再恢复 | 同局不重复播放已触发星级 |
| Combo ×2/3/4 等级上升 | 仅首次升级特殊震，其他正确上菜只有清脆 90ms |
| 真实拒单/乱序/超时/起火 | 保留 v1.6 长低频和明确区分，不被星级轻提示覆盖紧急危险 |
| 本地 2～4 手柄 | 对所属队伍手柄星级震动，但本机音效只播一次 |
| 15 分钟连续游玩 | 无震动噪音、无重复声音、无持续马达、按键响应不受影响 |

自动单测只代表逻辑通过，真实游戏 Hook 和实体手柄触感另行标注；不可把配置写完当成“游戏已适配”。

## 8. 待 AI 主动提出但不可擅自决定的问题

- 三星音效应使用“胜利小号短句”还是“欢快木琴/钢琴短句”？先提供 2～3 个素材/试听样本和理由；**未获用户批准不擅自更换音乐风格**。
- 四星 10 秒音乐是否会过长？默认按确认需求执行，提出可选低音量/快淡出预设但不要擅自缩短。
- 可选视觉提示是否改变游戏 UI？默认关闭，只提出不遮挡订单区的设计草案供用户确认。
