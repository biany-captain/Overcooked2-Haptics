# 0.2.3 新版数据校准

目的：在真实游戏中验证比分、顺序判据、Combo 和星级门槛来源。已有震动沿用 0.2.2；本轮不试听尚未启用的新波形。

## 准备

启用 `[Diagnostics] ScoreSourceProbe = true`，重新启动游戏。日志应有 `0.2.3-alpha` 和 `Score source probe installed`。安装日志只证明 Patch 装载。

选择方便重复交付、至少有两种订单的普通关卡。记录世界地图上 1/2/3 星分数线；如当前存档已允许四星，也记录第四线，无需为测试修改存档或解锁进度。

## 一轮操作

1. 从正常开局开始，依次交付最左侧有效订单 6 次，观察每次 HUD 的倍率；尤其第一单和第 5、6 单。
2. 跳过最左订单，交付另一张有效订单一次，再正常顺序交付两次，观察倍率中断和恢复。
3. 错误上菜一次，再让一个订单真正超时，观察各自对倍率的影响。
4. 如实际分数能跨过 1/2/3 星线，记录当时 HUD 分数；不要求为本轮强行达到四星。
5. 退出游戏保存本轮日志，报告看到的倍率和地图分数线。次数不同也可以，说明实际顺序即可。

## 对照规则

`observation` 是本地日志序号，**不是游戏权威 commitId**。`localRound` 来自场景/关卡生命周期和客户端实例，也不是网络 RoundId。`before`、`payload`、`after` 为冻结的数值副本，不能因游戏复用对象而改变。

- `result=AppliedClientState`：应用后数值与收到的消息一致，仅证明同步路径相符。
- `rawMultiplier`：当前候选 HUD 倍率，逐次与画面比较后才能认定已校准。
- `rawTotalCombo`：原始游戏计数，保留超过 4 的值，不等同于显示倍率。
- `thresholdCandidate`：通过基本合法性与关卡配置匹配的候选门槛，仍需地图/结算对照。
- `fourthAvailable`：本关 NGP 可用且游戏 NGP 提示已显示；第四门槛缺失/无效时不能开放。
- `Unavailable` / `PayloadClientMismatch`：记录原始情况，相关新功能保持未验证。

本机一手柄为当前范围；双手柄、其他队伍、在线客机及四星环境各自需要后续真实测试。不要用本轮单机通过推断其他场景已支持。
