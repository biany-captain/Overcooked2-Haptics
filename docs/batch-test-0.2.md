# 0.2 整批实机测试

目标设备和绑定沿用已验证的黑武士5 Pro / 2.4G XInput / 游戏Pad0→XInput0。总倍率0.75，F6测试，F10总开关。新增四类事件先全部开启，测试日志开启。

一次启动游戏即可测试整批。每个独立动作尽量间隔一秒，先观察单个模式，再观察同时发生时的优先级。多个事件重叠时低优先级被打断/丢弃是当前已确认策略。

| 测试项 | 实际操作 | 预期 |
|---|---|---|
| 原有投掷回归 | 投出食材，再空手按投掷键 | 成功时短震，空手无反馈 |
| 上菜成功 | 正确完成并交付一个当前订单 | 短双震，中间有间隔 |
| 上菜失败 | 做一次被游戏明确判为错误上菜的交付 | 偏低频单次长震 |
| 订单超时 | 让一张订单自身倒计时归零，关卡仍在进行 | 一次较明显的双马达长震；不是提前提醒 |
| 厨师接住 | 让另一厨师投来食材，用接收厨师接住 | 一次90ms接住反馈；拾起地上食材不算接住 |
| 总开关回归 | F10关闭后再投掷；随后F10重新开启 | 关闭后不震，重新启用后正常 |

上菜口拒绝一个不接受的物品，未必进入“错误订单交付”事件；请以游戏实际失败提示为准。接住当前走本地/房主路径；单人切换厨师不好操作时可先把该项记作未测，或在自己作为房主时请另一玩家投来。不要为测试改动关卡、分数或存档。

完成后退出游戏，按以下格式反馈即可，无需每项重启：

- 接住：正常 / 未测 / 异常描述
- 上菜成功：能辨认双震 / 未触发 / 其他
- 上菜失败：正常 / 未测 / 异常描述
- 订单超时：正常 / 未测 / 异常描述
- 原有投掷和F10：正常 / 异常描述

日志会分别记录 Hook 安装、实际事件、路由和安排震动的计数。`accepted=True` 仅代表调度器接受，体感与完整播放仍需用户观察；后续更高优先级事件可能打断它。
