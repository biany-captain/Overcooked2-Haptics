# v1.3 需求的分阶段实现设计

正式需求：[requirements-v1.3.md](requirements-v1.3.md)。当前可回退基线为插件 0.2.2；需求版本号与插件版本号分别管理。

## 已确认的体验

2026-11-21 用户明确选择文档标准方案并要求整批实测：

- 顺序/乱序成功上菜按 §4.3 分类和参数，未知分类保守降级。
- Combo 默认 EveryOrderedDelivery，使用真实已同步倍率，每次可信顺序交付只选择一套最终波形。
- 星级采用 §19.3 庆祝序列、原创清脆奖励音，候选音量 0.65；四种声音/震动组合模式可切换。
- 纯震动的一星增加轻尾脉冲，接住改为两段短震，参数在实测前列出供比较。
- 保留 F6 管理页、F10 总开关、菜单不自动暂停及当前绑定规则；多手柄和在线验证仍后置。

文档四星序列逐段相加为 **500ms**，850ms 是最大允许值，不为凑满上限延长波形。以上都是首轮候选手感，未经用户体验不标记最终通过。

## 现状与差距

0.2.2 只有通用成功上菜双震，并没有文档所假定的“v1.2 已完成”状态。需要先实现分类/Combo 基础，再接入星级仲裁。投掷、接住、失败、过期及菜单已有实机记录。

## 技术路线与取舍

沿用一个 net35/x86 插件、现有 BepInEx/Harmony/XInput 和纯 C# 核心，不新增运行依赖。优先消费客户端确认消息；仅有服务器线索或未经校准的推导值不作为已验证等级。

当前程序集的只读 IL 证据：

- `ClientKitchenFlowControllerBase.ApplyServerEvent` 先复制消息的 TeamScoreStats，再分派成功/失败/过期事件。
- `ScoreUIController.ScoreUpdate` 直接读取 TotalMultiplier；总分调用 GetTotalScore，而非 UI 滚动动画数值。
- 服务器成功事件在发送前更新 TotalMultiplier 和 TotalCombo；TotalCombo 保留超过四次的计数，倍率封顶四档。
- `IsComboOrder` 对初始起步也检查实际订单 ID 的位置，不使用 tip 判断。
- 当前关卡 SceneDirectoryVarientEntry 提供按平台/人数选择的分数线。游戏评星还检查 IsNGPEnabledForLevel 与 NewGamePlusDialogShown，不能仅因为存在 FourStarScore 就开放四星。

这些是静态证据，不等于实机校准。替代路线为本地推导 Combo 或硬编码分数表，容易在中途加入、失同步和不同模式误报，因此暂不启用。

## 实施次序与验收门槛

1. **0.2.3 校准版：** 添加独立、可关闭、只记录日志的比分探针，不提交任何新震动/声音。记录同步前后分数、倍率、连续次数、订单 ID、wasCombo、tip、关卡/模式/人数、3/4 星门槛及数据适用性。原有五类事件和菜单保持已验证行为。
2. 对照用户游戏 HUD 和世界地图门槛，确认首单、连续正确交付、乱序恢复、失败及超时的语义。无四星环境时明确保留四星未验证。
3. 在证据基础上实现 DeliveryClassifier、ComboTracker、可调候选预设及配置迁移。Unknown 不猜倍率；一次交付只输出一类反馈。
4. 实现 StarMilestoneTracker、同消息立即仲裁的 CelebrationCoordinator 和 Unity 原创 PCM 音效后端。用户在真实数据证明同消息包含比分/交付后确认取消统一120ms等待；未来异步来源另行验证。中途启用不补播，分数下降再回升不重播，跨多星只庆祝最高星。
5. 接入现有 F6 的相应设置与试震；列明新增波形参数，做整批游戏验收和辨识度比较。额外动画、字幕、音频导入、危险事件扩展均不在本轮直接加入。

## 保护边界

只读 Hook，不更改得分、订单、存档和网络数据。独立探针异常只停探针，不关闭已有反馈。未来音频失败只停音频；失焦/暂停/切关/禁用停音停震。危险事件抢占并丢弃过期奖励，不补播。

## Git 与交付

用户已授权提交和推送必要文件。保留已验证基线提交；新版使用独立功能分支。跟踪源码、测试、脚本、配置示例、需求及验证说明；忽略中间产物、安装环境、个人配置和本地执行记录。项目许可证暂未选择，不擅自指定。
