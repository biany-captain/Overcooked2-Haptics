## 本轮行为

- Combo A：只在可靠游戏倍率确认升级到×2/×3/×4时播放专属节奏。同档、封顶后继续交付只有一次90ms普通成功；与星级不叠加。
- 乱序成功需要可信先前连击与本次中断；单独wasCombo=false、首单、未知等级不猜乱序，采用普通成功。真正拒单和订单已超时独立处理。
- 同一已验证客户端消息立即选择一种最终反馈，沿用已批准路径；不额外统一等待80ms。失败/超时的捕获与备用Hook共用所有权，避免双提交。
- 同次达星优先星级；之后发生另一笔拒单/超时可打断当前庆祝。起火/危险更高，普通动作和成功不打断音乐尾声。抢占不排队补播旧反馈。
- 新危险反馈是**客户端状态候选**：起火归并场景内事故，蔓延不逐火焰连震；持续提醒至多每5秒一次，扑灭即取消。近烧焦用客户端OverDoing状态边沿，是否与预期危险时机吻合需实测；已烧焦Ruined只探测、默认不自动震动。
- 投掷/接住保留Hook和试震，按v1.6默认关闭自动反馈；拾取/连续切菜等未增加。

## 候选波形

数值为XInput低频左/高频右命令，不是物理频率或体感百分比。只乘总震动强度，新用户默认0.75；保留现有个人值。原额外Combo0.85移除，避免再次衰减。

| 事件 | 左/右片段（0..1），间隔为静默 | 总长 |
|---|---|---:|
| 成功／未分类成功 | .02/.72×90ms |90ms|
| 乱序但成功 | .29/.02×125 → 停90 → .17/0×100 |315ms|
| 真正拒单 | .72/.02×210 → .47/0×95 → .24/0×125 |430ms|
| Combo×2升级 | 0/.49×70 → 停70 → 0/.66×95 |235ms|
| Combo×3升级 | 0/.47×65 → 停65 → 0/.55×70 → 停65 → 0/.72×110 |375ms|
| Combo×4升级 | 0/.47×60 → 停60 → 0/.55×60 → 停60 → 0/.62×60 → 停60 → .12/.79×130 |490ms|
| 订单已超时 | .61/.02×190 → 停85 → .55/0×230 |505ms|
| 近烧焦警告 | .44/.09×150 → 停120 → .52/.09×180 |450ms|
| 已烧焦（自动默认关） | .66/0×230 → .45/0×90 → .23/0×150 |470ms|
| 起火 | .81/.10×260 → 停90 → .69/.06×310 → .30/0×160 |820ms|
| 持续火警 | .42/.08×160 → 停130 → .42/.08×180 |470ms|

投掷75ms、接住205ms默认关；通用试震仍80ms。星级仍180/285/425/660ms，不延长或重编原音乐。每段上限500ms，普通模式500ms、星级850ms、负面/危险950ms。完整候选源见[JSON](config/haptic_patterns_v1.6.json)，构建时验证生成的默认值与其一致；运行沿用BepInEx配置，无新JSON运行库。

## 设备与兼容

只监听游戏事件，不改分数、订单、存档、网络或人物动作。WindowsSteam默认x86分支、Unity2017.4.8、BepInEx5.4.22.0是当前开发环境，不代表其他分支已支持。

设备索引与游戏Pad不同，默认都-1，必须显式绑定。本机曾验证黑武士5Pro、2.4G XInput、Pad0→XInput0；更换设备或模式后重新确认。XInput的左右通道属于基础接口，不是高级专有触觉。

上菜消息没有直接厨师ID。只有能证明同队参与者共用一个本地输出设备时才推定输出；未知多人/在线操作者的Combo静默。普通交付可在cfg明确允许队伍回退后，仅通知所选绑定，不自动广播。危险限当前Campaign及可靠本地队伍映射；对战/未知队伍不猜。

中央协调器统一去重、优先级、过时丢弃、每设备冷却和预算。预算按已执行排程的非零时长估算，10秒普通1200ms/负面2200ms/紧急2500ms；不是物理测量或医学限值。超预算星级仍可播放音效，日志如实记录马达未安排。断连、暂停、失焦、切关、卸载停止自有输出；主线程卡死/强制结束/驱动异常仍不能保证物理停震延迟。

SDL3仅有[扩展与独占契约](docs/backend-extension.md)及模拟验证，未加载原生库或新增驱动。身份不明时拒绝跨后端并行；不按同名设备猜物理身份，也不承诺控制其他软件的输出。本地多手柄、在线和虚拟设备物理去重仍需独立实测。

## 安装与绑定

1. 正常退出游戏，保留现有BepInEx与其他MOD。将安装包 `BepInEx/plugins/OC2Haptic/` 复制到游戏对应目录；只复制DLL将缺失新安装所需音乐。已有0.4.2音频未变，可仅升级自身DLL。
2. 不用示例cfg覆盖个人配置。启动会将精确匹配的旧默认波形迁移到v1.6，自定义精度和无效波形原文保留；旧默认与新值对照见报告。
3. 配置为 `BepInEx/config/dev.oc2haptic.feedback.cfg`，设置 `Devices.XInputIndex=0..3`、`LocalGamePadSlot=真实游戏Pad`。F6通用试震确认目标；无把握时保持-1。
4. 检查 `OC2Haptic initialized | 0.5.1-alpha v1.6 candidate` 和候选Hook安装日志。安装成功不等于Hook/硬件验收通过，按整批测试清单记录。

## F6与配置

- 页面保留震动总开关＋总强度、音效总开关＋相对音量，两个滑杆均0–100%。F10任一路开启时全关，两路关闭时全开；F6始终可打开。
- 「设置」顶部新增三个自动反馈开关：星级庆祝·震动、星级庆祝·音效、危险预警·震动。星级可选只音效、只震动或两者；两项都关时恢复普通上菜/Combo仲裁。危险组包含近烧焦/已烧焦/首次起火/持续提醒，不含拒单和订单超时，仍服从各事件cfg。关闭只停止相应输出；开启不补播。F10保留三项偏好。
- 「设置」中逐项试震；「星级测试」保留四星的试音/试震/同时测试及音效包下拉。手动测试可比较默认关闭的自动事件，但必须服从两个总控、预算与冷却。
- 不自动暂停，只屏蔽绑定本地厨师并显示鼠标。关闭恢复操作；关卡仍运行，调试可先手动暂停。关菜单/失焦立即停止，不补播。
- `General`：HapticsEnabled、AudioEnabled、MasterIntensity；保留个人值。
- `Events`：各自动反馈开关，ThrowSuccess/CatchSuccess/FoodBurned默认false；持续火灾用FireReminder可关闭。
- `Combo.Enabled`控制分级，方案固定A；`Stars.HapticsEnabled`、`Stars.AudioEnabled`和`Hazards.HapticsEnabled`对应三项功能开关。旧`Stars.Enabled`迁移为星级两项，有明确新值时优先新值。无需恢复事件倍率或四种模式菜单。
- `Routing.AllowTeamDeliveryFallback`、`AllowTeamHazardFallback`默认false，不能开启猜测Combo或全设备广播。
- `Patterns`可编辑片段，严格校验范围/长度/时长；非法值只静音对应震动，改设置时日志提示。手动编辑cfg先退出游戏，菜单修改即时保存；没有cfg文件监视热重载。

相对音量默认100%，跟随游戏主音量/SFX，可单独调低；本轮不采用文档旧65%覆盖用户偏好。三套音乐仍为超燃卡通大乐队（默认）、冠军加冕号角、厨房摇滚派对，原样12WAV，四星3.80–4.05秒。来源、GPL/SoundFont署名、MIDI和制作脚本见[资产记录](assets/audio/SOURCES.md)，不称CC0或独立版权审定。代码许可证尚待负责人选择。

## 开发与回退

开发需要.NET SDK10及本地匹配游戏程序集，安装插件不需要.NET10。不下载NuGet包，不分发游戏DLL。

```powershell
./scripts/test.ps1
./scripts/test-config.ps1
./scripts/test-probe.ps1
./scripts/build.ps1 -GameRoot 'E:\SteamLibrary\steamapps\common\Overcooked! 2'
./scripts/package.ps1 -SkipBuild
```

修改JSON后执行 `./scripts/generate-haptic-preset.ps1`，构建会检查生成内容。所有软件测试、静态证据与原生手工结果分层记录；新的危险事件、完整多人矩阵、NGP四星及真实同步延迟未完成验收。

输出在artifacts，Git忽略构建/缓存/安装ZIP/个人cfg。退出游戏后恢复冷备份DLL与cfg可回退；删除本插件目录可卸载，不改原版存档或其他MOD。PR继续为草稿，未合并main。
