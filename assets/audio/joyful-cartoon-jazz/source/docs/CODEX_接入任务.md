# Codex：接入星级达成庆祝音频（仅增量修改）

请检查当前 `Overcooked2-Haptics` 仓库的架构、实际 BepInEx 运行版本和已有的星级状态追踪，不要重建项目。新增四星庆祝音乐播放，但不改变任何游戏计分逻辑。

## 接入资源

- `audio_ogg/star_1_playful_spark.ogg`
- `audio_ogg/star_2_bouncy_skip.ogg`
- `audio_ogg/star_3_brass_victory.ogg`
- `audio_ogg/star_4_grand_kitchen_party.ogg`

可根据当前 Unity 版本采用它支持且已验证的 AudioClip 加载方式（资源嵌入/AssetBundle/文件读取）。OGG 解码需要确认本机实际可用，不能仅凭文档推断。所有音频启动前预加载，不允许在分数变动的 Hook 中同步解码/磁盘读取或阻塞。

## 用户已确认默认偏好

- 风格：**庆祝型 / 欢乐卡通爵士 / 随星级越高越热闹**
- 反馈：`震动 + 音效`
- 音量：`0.65`
- 4 星：`少量卡通欢呼 + 掌声`，目前音频含自行合成拟声，**并非真实录音**
- 每星音乐必须明显不同，星级越高胜利感越强。

## 行为约束

- 真实关卡实时分数首次跨越真实星级分数线才播放；阈值未知时不触发。
- 同一局单个星级只播放一次；单次上菜跨多个星级播放最高星级的一首；同次普通上菜、Combo、星级只允许一条庆祝路径。
- 4 星只是 New Game+ 等模式下可能存在，不要硬假设全部关卡都有四颗星。
- 火灾/危险警告优先，必要时停止庆祝音并释放所有手柄马达。
- 一个本地游戏实例的队伍星级庆祝声音只播放一次，不应因 1～4 个手柄而重复播放。
- 更换关卡/重启/暂停/断开连接/卸载时及时停止音乐及震动。

## 建议同步时间点（毫秒，时间 0 为音频播放基准点）

- 1星：`[0, 420]`；第二下极轻；总震动窗口 470ms。
- 2星：`[0, 490, 1005]`；短且递进；结束于 1100ms。
- 3星：`[0, 285, 755]`；最后重音；结束于 930ms。
- 4星：`[0, 120, 455, 680]`；四次辨识度高的庆祝震动；结束于 830ms。4 星人声/掌声主要位于音频 2310～3200ms，不需随尾音持续震动。

注意：这些时间点是候选方案而非用户真实手柄实测定稿。音频相对马达的启动延迟需实机标定，可按 `docs/star_celebration_config.json` 配置。震动模式不得在同次事件上叠加。

## 最小验收

1. 本地试听四首时音频长度、文件头、格式正确；不存在数字削波或末尾咔哒。
2. 真正跨越各星级门槛时能播放正确曲目，且不会因重复 Hook 重放。
3. 同一次上菜导致 Combo 和星级提升时不串音。
4. 庆祝期间紧急预警正确抢占；中断后马达必归零。
5. 断连、重开及多玩家情况下不会重复播放/漏停止。
6. 默认 65% 音量且可独立关闭；不要修改游戏全局 BGM。
7. 以 **听觉盲测辨识度≥85%** 作为调整目标（尚未完成真人盲测）；向用户反馈测试结果，并在修改最终旋律/配器前询问用户。

**协作要求：** 用户重视主动询问和建议。变更音乐风格、旋律、默认行为或加入新音效素材前，向用户说明理由、成本和备选，征得同意。一般编译、修复可自动推进。
